## 목표 아키텍처와 계약

### 레이어 구조

- Control plane layer
  - repo-neutral agent manifests, capability registry, hook intents, handoff contracts
- Context router layer
  - task를 보고 domain bundle을 조립
- Capability layer
  - PromptOps / Scraper / Front / Back capability pack
- Runner layer
  - task spec -> context bundle -> validation suite -> handoff
- Product runtime layer
  - 기존 FastAPI / LangGraph / Next.js / scraper 모듈 유지

### 내부 계약

#### `TaskSpec`

- `domain`
- `objective`
- `allowed_surfaces`
- `expected_artifacts`
- `required_validations`

#### `ContextBundle`

- `global`
- `product`
- `domain`
- `task_delta`
- `docs_references`
- `validation`

#### `AgentResult`

- `outcome_summary`
- `changed_surfaces`
- `evidence`
- `follow_up_or_handoff`

#### `ValidationSuite`

- `commands`
- `smoke_cases`
- `required_doc_updates`

### 표준 운영 규칙

- canonical source는 assistant-neutral 문서/manifest가 소유합니다.
- assistant 디렉토리는 adapter이지 owner가 아닙니다.
- 각 domain pack은 파일, 테스트, 문서, handoff를 함께 소유합니다.
- hook는 business logic를 갖지 않습니다.
- context는 layered and bounded 원칙을 유지합니다.
- public product API는 agent runtime evolution과 decoupled 상태를 유지합니다.
