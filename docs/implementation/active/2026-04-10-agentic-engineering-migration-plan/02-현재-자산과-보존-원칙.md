## 현재 자산과 보존 원칙

### 이미 갖고 있는 강점

- `main` 기준 worktree bootstrap과 branch discipline
- `docs/implementation/active/` 중심의 plan package lifecycle
- `FastAPI -> PipelineTriggerService -> LangGraph nodes`로 이어지는 product runtime seam
- `src/common/user_preferences.py`, `src/promptops/projects/ai_career_concierge/context.py`의 normalized context 구성
- `src/promptops/core/*`, `src/promptops/adapters/langsmith.py`, project binding으로 시작된 PromptOps 분리 시도
- LangSmith tracing seam과 docs-backed operations panel

### 반드시 보존할 것

- LangGraph node 책임 분리 자체는 유지합니다.
- normalized evaluation context 원칙은 유지합니다.
- prompt family registry와 LangSmith adapter seam은 방향을 살립니다.
- worktree discipline과 plan-save/archive discipline은 migration 이후에도 기본 운영 단위로 유지합니다.
- `/api/v1/*` public product API는 초기 migration 범위 밖으로 둡니다.

### preserve vs replace 원칙

- 잘 동작하는 product runtime은 preserve합니다.
- assistant-specific ownership은 replace합니다.
- 암묵 규칙과 markdown-only 계약은 가능한 범위에서 manifest/structured snapshot으로 승격합니다.
- hook는 business logic를 가지지 않고 control point 역할만 하도록 재정의합니다.
