## 단계별 마이그레이션 계획

### 1. Canonical control plane을 assistant-neutral로 승격

- 새 canonical 경로: `.agents/registry/`, `.agents/hooks/`, `.agents/capabilities/`
- 포함 항목: agent manifests, task spec schema, capability registry, hook intents
- `.claude/`, `.gemini/`, Codex instructions는 shared config를 호출하는 thin adapter만 남깁니다.

### 2. Implicit rules를 first-class capability pack으로 추출

- 현재 `.claude/rules/*.md`에 흩어진 규칙을 PromptOps / Scraper / Front / Back capability pack으로 승격합니다.
- 각 pack은 purpose, inputs, allowed files, required context, commands, validation, handoff format을 포함합니다.

### 3. Context engineering을 routing layer로 확장

- 새 계층: `src/agentic/context/`
- 핵심 모델: `TaskContextBundle`
- bundle 층위:
  - global repo context
  - product contract context
  - domain context
  - task-local delta
  - validation context

### 4. PromptOps를 독립 capability로 decouple

- `src/promptops/adapters/langsmith.py`, `src/promptops/run_iteration.py`, `src/promptops/core/*` 경계 재정의
- PromptOps orchestration은 evaluator target interface, dataset source interface, review backend interface를 주입받도록 바꿉니다.

### 5. Prompt ownership을 family package로 이동

- `PromptManager`는 resolution/rendering/metadata trace만 담당하게 줄입니다.
- family별 fallback prompt, policy, schema binding은 project prompt family package가 소유합니다.

### 6. Role-specific runner 도입

- 새 runner: `PromptOpsRunner`, `ScraperRunner`, `FrontRunner`, `BackRunner`
- 각 runner는 owned surfaces, required context, validation suite, handoff contract를 가집니다.

### 7. Hook를 control point로 재정의

- hook 역할: preflight, context-pack publish, post-task validation, plan-save, handoff summary
- assistant-specific 설정 파일에는 matcher/dispatch만 남기고 행위는 shared script로 수렴시킵니다.

### 8. Status surface를 live contract 기반으로 전환

- `src/api/services/promptops_status_service.py`는 hardcoded snapshot 대신 registry + snapshot fetcher에서 값을 읽도록 바꿉니다.
- `/internal/prompts` UI 응답 shape는 유지합니다.

### 9. Medium-term: product runtime composition 분리

- `src/api/services/pipeline_trigger_service.py`와 `src/api/services/runtime.py`에서 graph assembly / runtime assembly를 builder 또는 factory로 분리합니다.
- 목표는 Back / Scraper 작업이 route/service 전체를 과도하게 건드리지 않게 하는 것입니다.

### 실행 우선순위

1. `.agents/` canonical layer와 capability registry 도입
2. context bundle / task routing fixture 도입
3. PromptOps decoupling과 prompt ownership 정리
4. role-specific runner / shared hook 수렴
5. status surface live contract화
6. product runtime composition 추가 분리
