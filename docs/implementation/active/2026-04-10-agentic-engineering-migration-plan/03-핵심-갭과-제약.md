## 핵심 갭과 제약

### 현재 구조의 핵심 갭

- 현재 시스템은 전문 서브에이전트 집합보다는 단일 product runtime + 운영 helper에 가깝습니다.
- `src/promptops/adapters/langsmith.py`가 agent runtime 요소를 직접 가져와 adapter 경계가 흐립니다.
- PromptOps core 일부가 placeholder 수준에 머물러 capability contract가 비어 있습니다.
- fallback prompt와 policy ownership이 runtime prompt manager 깊숙이 들어가 있습니다.
- hook가 guard/save glue에는 유용하지만 routing, context packaging, handoff validation에는 약합니다.
- assistant별 canonical source가 분산돼 있어 Codex/Claude parity가 구조가 아니라 관례에 의존합니다.
- Front / Back / Scraper / PromptOps 각각에 대해 입력 계약, 허용 surface, 검증, handoff format이 정의돼 있지 않습니다.
- `src/api/services/promptops_status_service.py`와 docs 파서 일부가 hardcoded snapshot 및 markdown phrase shape에 강하게 결합돼 있습니다.

### 제약

- 현재 PoC 핵심 루프 안정성이 agentic abstraction보다 우선입니다.
- LangSmith experiment flow를 깨면 PromptOps 운영 가치가 크게 줄어듭니다.
- markdown 기반 operations panel을 한 번에 제거하기보다 structured snapshot 병행으로 점진 전환해야 합니다.
- 로컬 개발 환경 제약 때문에 모든 검증이 즉시 실행되지는 않을 수 있으므로, fixture 기반 테스트와 CI 기준선을 함께 유지해야 합니다.
