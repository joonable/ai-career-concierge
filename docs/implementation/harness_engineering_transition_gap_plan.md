# 하네스 엔지니어링 전환 보완 계획

작성일: 2026-04-10

## 개요

이 문서는 현재 저장소의 하네스 엔지니어링 전환 상태를 실제 파일/설정/검증 결과 기준으로 점검한 뒤, 부족한 부분과 후속 보완 순서를 정리한 실행 보조 문서입니다.

`TODO.md`가 단기 실행 체크리스트를 담당한다면, 이 문서는 왜 해당 작업이 필요한지와 어떤 순서로 정리해야 하는지를 설명하는 맥락 문서입니다.

## 현재 상태 요약

다음 항목은 이미 저장소에 반영되어 있으나, 기존 `TODO.md`에는 미완료처럼 남아 있거나 충분히 반영되지 않았습니다.

- `CLAUDE.md` 생성 완료
- `AGENTS.md` 슬림화 완료
- `.claude/rules/` 8개 도메인 규칙 파일 생성 완료
- `.claude/settings.json` 생성 완료
- `MILESTONE.md` 생성 완료
- `ruff` 설정 및 CI 구성 완료
- `.github/workflows/ci.yml` 생성 완료
- `.claude/rules/promptops.md` 내 에이전트 워크플로우 규칙 반영 완료

즉, 현재 필요한 일은 “하네스 기반의 구조를 새로 만드는 것”보다, 이미 만들어진 구조를 문서와 체크리스트에 정확하게 반영하고 남은 공백만 선별하는 것입니다.

## 실제 부족한 부분

### 1. 문서/추적 체계 정합성 부족

- `TODO.md`, `MILESTONE.md`, 실제 저장소 상태가 서로 완전히 일치하지 않습니다.
- 완료된 항목이 계속 미완료로 보이기 때문에, 병렬 작업 중인 에이전트가 잘못된 우선순위를 잡을 가능성이 있습니다.
- `TODO.md`는 실행 보드 역할을 해야 하지만, 현재는 과거 설계 메모와 실제 진행 상황이 섞여 있습니다.

### 2. 세션/워크트리 운영 hygiene 미정리

- `.claude/sessions/` 체계는 계획에 있으나 실제 디렉토리/템플릿이 없습니다.
- `.claude/worktrees/`는 현재 로컬 병렬 작업 산출물이 쌓여 있으나, canonical source와의 경계가 문서와 ignore 규칙에서 충분히 정리되지 않았습니다.
- 병렬 작업 기준에서 루트 저장소와 worktree의 역할이 문서로 명시되어야 합니다.

### 3. 프론트엔드 계약 드리프트

검증 기준선 결과:

- `poetry run pytest tests/unit -q` → pass (`59 passed`)
- `cd apps/web && npm run typecheck` → pass
- `cd apps/web && npm run test` → fail (`5 failed`)

현재 실패의 핵심은 다음과 같습니다.

- `preferences` shape를 기대하는 대시보드 로직과 오래된 테스트 mock 간 불일치
- `/internal` 페이지가 기대하는 `internalStatus` shape와 테스트 mock 간 불일치
- `docs/promptops/status.md` 파서 테스트가 현재 문서 문구와 과도하게 결합되어 있음

즉, 하네스 전환 이후 문서/타입 계약이 바뀌었지만 테스트와 일부 소비 코드가 이를 충분히 따라오지 못한 상태입니다.

### 4. 기능 확장 backlog는 아직 남아 있음

다음 항목은 실제 미완료 backlog로 유지되어야 합니다.

- `Jobkorea` 멀티소스 스크래퍼 구현
- PromptOps 자동 분석/큐레이션 워크플로우 확장
- 규칙 필터 개선 분석 자동화

이들은 문서 정리 이후의 “실제 구현 작업”으로 다뤄야 합니다.

## 우선순위 재정렬

하네스 전환 이후의 남은 작업은 아래 순서로 다루는 것이 가장 안전합니다.

1. 문서 정합성 복구
   - `TODO.md`를 실제 상태 기준으로 재작성
   - 완료/미완료 상태를 저장소 현실과 맞춤
2. 프론트엔드 계약 안정화
   - `apps/web` 테스트 실패 5건 복구
   - 문서 파서/대시보드 profile shape 호환성 보강
3. 운영 hygiene 정리
   - `.claude/sessions/` 체계 실물 생성
   - `.claude/worktrees/` 로컬 산출물 관리 규칙 반영
4. 기능 확장
   - `Jobkorea` 멀티소스 구현
   - PromptOps 자동 분석/큐레이션 확장

## 작업 원칙

- 외부 API 계약은 이번 문서 정리 작업에서 변경하지 않습니다.
- `TODO.md`는 canonical short-term execution board로 유지합니다.
- 이 문서는 상세 맥락과 우선순위를 설명하는 companion document 역할만 수행합니다.
- 이미 존재하는 산출물을 다시 “계획 중”으로 보이게 하지 않습니다.
- 병렬 작업 중인 에이전트가 바로 이해할 수 있게, 완료된 것과 미완료를 명확히 구분합니다.

## 검증 기준

문서 정리 이후에도 기준선은 다음처럼 유지되어야 합니다.

- `poetry run pytest tests/unit -q` → pass
- `cd apps/web && npm run typecheck` → pass
- `cd apps/web && npm run test` → fail 5건 상태를 문서에 명시적으로 기록

이번 작업은 문서 정합화가 목적이므로, 프론트엔드 실패를 고치지 않고도 현재 기준선을 정확히 기록하는 것이 중요합니다.
