## 실제 부족한 부분

### 1. 문서/추적 체계 정합성 부족

- `TODO.md`, `MILESTONE.md`, 실제 저장소 상태가 서로 완전히 일치하지 않습니다.
- 완료된 항목이 계속 미완료로 보이기 때문에, 병렬 작업 중인 에이전트가 잘못된 우선순위를 잡을 가능성이 있습니다.
- `TODO.md`는 실행 보드 역할을 해야 하지만, 현재는 과거 설계 메모와 실제 진행 상황이 섞여 있습니다.

### 2. 세션/워크트리 운영 hygiene 미정리

- `.claude/sessions/` 체계는 계획에 있으나 실제 디렉토리/템플릿이 없습니다.
- `.claude/worktrees/`는 현재 로컬 병렬 작업 산출물이 쌓여 있으나, canonical source와의 경계가 문서와 ignore 규칙에서 충분히 정리되지 않았습니다.
- 병렬 작업 기준에서 루트 저장소와 worktree의 역할이 문서로 명시되어야 합니다.

### 3. 프론트엔드 계약 드리프트

검증 기준선 결과:

- `poetry run pytest tests/unit -q` → pass (`59 passed`)
- `cd apps/web && npm run typecheck` → pass
- `cd apps/web && npm run test` → fail (`5 failed`)

현재 실패의 핵심은 다음과 같습니다.

- `preferences` shape를 기대하는 대시보드 로직과 오래된 테스트 mock 간 불일치
- `/internal` 페이지가 기대하는 `internalStatus` shape와 테스트 mock 간 불일치
- `docs/promptops/status.md` 파서 테스트가 현재 문서 문구와 과도하게 결합되어 있음

즉, 하네스 전환 이후 문서/타입 계약이 바뀌었지만 테스트와 일부 소비 코드가 이를 충분히 따라오지 못한 상태입니다.

### 4. 기능 확장 backlog는 아직 남아 있음

다음 항목은 실제 미완료 backlog로 유지되어야 합니다.

- `Jobkorea` 멀티소스 스크래퍼 구현
- PromptOps 자동 분석/큐레이션 워크플로우 확장
- 규칙 필터 개선 분석 자동화

이들은 문서 정리 이후의 “실제 구현 작업”으로 다뤄야 합니다.
